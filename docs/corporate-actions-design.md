# 무상증자와 주식 수 변동 처리 설계

작성일: 2026-09-20. 최종 반영: 2026-09-21. 상태: 운영 DB·웹 배포 및 RF머트리얼즈 1:1 반영 완료.

## 구현 진행 상태

- `js/utils/corporate-actions.js`: 권리락·입고·매수·매도 재생, 단수/중복/초과 매도 차단, 기준가 환산.
- `corporate-actions.html`: 공시 프리셋, 서버 미리보기, 적용, 입고 확인 화면. 로컬 테스트 데이터로 모바일 화면 검증.
- `js/corporate-actions-service.js`: 버전 확인과 서버 잔고 연결. 서버가 미설치이면 기존 잔고를 유지하고 관리 화면은 연결 대기를 표시한다.
- `sql/inspect-corporate-actions.sql`: 기존 운영 뷰·트리거·정책을 확인하는 읽기 전용 질의.
- 2026-09-20 운영 UI 확인: RF머트리얼즈 2026-04-12 매수 6주 × 75,500원. 현재 목록에는 이 종목의 매도 기록이 없음.
- 운영 배포: `sql/20260920-corporate-actions.sql`, 웹 캐시 버전 `20260921.1`.
- 서버 RPC: `sss_corporate_actions_version`, `sss_corporate_positions`, `sss_corporate_actions_list`, `sss_preview_bonus`, `sss_apply_bonus`, `sss_credit_bonus`, `sss_reverse_bonus`, `sss_submit_trade`.
- 검증: 웹 168개 테스트 통과. 운영 DB에서 임시 거래로 무상증자·입고·부분매도·결산·중복 요청·권한·취소 실패 롤백을 확인한 뒤 테스트 트랜잭션 전체 롤백.
- RF머트리얼즈 적용: 권리락 2026-07-24, 공시상 신주 상장일 2026-08-18을 입고일로 등록. 사용자 확인(이미 1:1 무상증자 완료)과 공시 일정을 근거로 스터디 원장에 반영했으며 증권사 계좌에는 접근하지 않았다.
- 운영 화면: 6주 → 12주, 평균 75,500원 → 37,750원, 원가 453,000원 유지, 매도 가능 12주. 기존 거래와 현금·기준금액 유지.
- 최초 구현은 기존 pick_id를 실제 포지션 식별자로 유지한다. 자동 이월 아이디어가 동일 보유를 복제하지 않도록 원거래가 있는 포지션만 평가하고 뷰의 중복 행은 접는다. 별도 position_id 마이그레이션은 하지 않았다.
- 단수주 및 이전 미입고 권리가 겹치는 사건은 자동 반영을 거절한다. 액면분할·병합 및 단수 현금정산은 확장 설계이며 이번 기능에 포함하지 않는다.
- 정정은 취소 이력을 남긴 뒤 재등록한다. 취소가 후속 매도의 잔고를 음수로 만들면 전체 취소 작업을 거절한다. 거래 원본은 수정·삭제 대신 보존한다.
- 기존 결산의 최초 매수가 기준 및 음수 수수료 문제를 새 계산에서 수정했다. 이후 거래와 무상증자로 영향을 받는 포지션에 한해 기존 반영액과 재계산액의 차이를 별도 결산 행으로 기록한다. 관계없는 과거 결산은 재작성하지 않는다.

## 목적

무상증자로 늘어난 주식과 조정된 평균 매수가를 홈, 보유종목, 회원 현황, 내 페이지, 매도 입력, 결산에 일관되게 반영한다. 최초 구현은 무상증자를 대상으로 한다. 액면분할·병합은 동일한 이벤트 구조를 사용하되 별도 계산 규칙으로 확장한다. 유상증자·현금배당은 무상증자 비율 계산으로 처리하지 않는다.

## 계산 원칙

예시: 권리락 직전 10주, 평균 매수가 75,500원, 총원가 755,000원.

| 항목 | 권리락 전 | 권리락 후·입고 전 | 신주 입고 후 |
| --- | ---: | ---: | ---: |
| 입고된 주식 | 10주 | 10주 | 20주 |
| 미입고 신주 권리 | 0주 | 10주 | 0주 |
| 평가 대상 수량 | 10주 | 20주 | 20주 |
| 매도 가능 수량 | 10주 | 10주 | 20주 |
| 평가용 평균 매수가 | 75,500원 | 37,750원 | 37,750원 |
| 총원가 | 755,000원 | 755,000원 | 755,000원 |

- 현금과 총원가는 무상증자 자체로 변하지 않는다. 신주 수령을 매수 지출이나 투자 수익으로 기록하지 않는다.
- 권리락일부터 신주 권리를 현재 주가로 추정 평가하고, 입고 전 수량을 별도 표시한다. 이는 증권사 잔고 대조를 위한 앱의 평가 정책이며 세무 계산이 아니다.
- 권리락 이후 매수분은 해당 무상증자 대상에서 제외한다. 권리락 이후 구주를 팔아도 이미 확정된 신주 권리는 유지한다.
- 입고 전 매도 시 조정된 평균 단가로 매도 원가를 차감하고, 미입고 신주에 배분된 원가는 유지한다.
- 예: 위 상태에서 구주 4주 매도 → 입고 주식 6주 + 미입고 10주, 남은 원가 604,000원. 신주 입고 후 16주.
- 여러 번 무상증자가 있으면 각 사건 직전 권리 대상 잔고로 순서대로 계산한다.
- 정수 주식과 단수 권리를 분리한다. 1:1 이외 비율에서 단수가 발생하면 공시의 단수 처리 방법과 실제 지급액을 기록하고, 임의 반올림이나 현금 생성은 하지 않는다.
- 최신 가격이 권리락 이전 가격이면 조정 수량에 바로 곱하지 않는다. 가격 기준 시각을 확인하고 최신 평가액을 미확정으로 표시한다.
- 금액 계산은 DB numeric으로 수행한다. 표시 단계에서만 반올림하고 매도·결산에는 반올림 전 원가를 사용한다.

## 저장 구조

매수·매도 원본은 보존하고 별도 기업행사 원장을 둔다.

### corporate_actions: 종목별 사건

- id, stock_code, market, action_type, revision, status(draft/applied/reversed).
- existing_shares, new_shares: 기존 몇 주당 신주 몇 주인지 분자·분모로 저장. 1:1은 각각 1이며 수량 배수는 2.
- ex_date, record_date, expected_credit_date, source_url, note.
- created_by, created_at, applied_by, applied_at, supersedes_id.
- 종목·시장·유형·권리락일 기준으로 활성 사건 중복을 차단한다. 정정은 기존 기록을 덮어쓰지 않고 새 버전으로 연결한다.

### corporate_action_entitlements: 회원별 권리와 원가 배분

- action_id, member_id, position_id, eligible_quantity, new_quantity, fractional_quantity.
- allocated_cost, credited_quantity, actual_credit_date, status, calculation_revision.
- 적용 전후 수량·평균가·총원가를 감사 내역으로 저장한다.
- 실제 증권 계좌/회원 단위로 단수 수량을 계산한 뒤 내부 포지션에 배분한다. 여러 pick으로 나뉘었다고 단수 절사를 중복하지 않는다.
- action_id + member_id + position_id + revision 유일성으로 중복 적용을 방지한다.

### 포지션 식별

월별 아이디어(pick)와 실제 보유 포지션을 분리할 수 있도록 position_id를 사용한다. 기존 거래의 pick_id는 보존하고 매핑한다. 자동 이월 아이디어가 같은 잔고를 중복 생성하지 않게 한다. 이름 대신 종목코드를 기준으로 사건을 연결한다. 코드나 거래 이력이 없는 잔고는 관리자가 최초 수량·원가·기준일을 확정해야 한다.

## 서버 계산과 적용

1. 관리자 입력 → 서버 미리보기 RPC로 권리락 직전 잔고 및 이후 거래를 재생한다. KST 영업일 기준으로 같은 날 사건은 장 시작 전, 거래는 이후 순서다.
2. 미리보기에는 회원별 수량·원가·매도손익·결산 차이, 단수, 누락 기록, 이미 보정된 잔고를 표시한다.
3. 적용 RPC는 관리자 권한을 서버에서 검사하고 해당 종목/포지션과 사건을 잠근다. 미리보기 이후 원장이 바뀌었다면 재조회하게 한다.
4. 사건 적용, 권리 생성, 이후 거래 재계산, 결산 차액 조정을 한 DB 트랜잭션에서 처리한다. 부분 성공을 남기지 않는다.
5. 신주 입고는 별도 이벤트로 기록한다. 예상일만으로 입고 완료 처리하지 않는다. 입고 수량만큼 미입고 권리에서 매도 가능 수량으로 전환한다.
6. 적용·입고·정정 요청에는 idempotency key를 사용한다. 재시도나 동시 클릭으로 수량이 다시 늘지 않는다.
7. 매도 저장도 서버 RPC에서 거래일 기준 잔고와 현재까지의 후속 거래를 검증한다. 과거 거래 추가가 미래의 음수 잔고를 만들면 거절한다. 기존 직접 insert 경로/RLS로 검증을 우회하지 못하게 한다.
8. 취소·정정은 후속 매도와 결산까지 다시 계산한다. 단순히 현재 수량을 나누지 않는다. 확정 결산은 변경 전 기록을 보존하고 연결된 보정 내역과 차액만 반영한다.

현재 base_amount에는 결산 손익이 반영되어 있으므로 재계산된 손익 전액을 다시 더하면 안 된다. 기존 반영액과 새 반영액의 차이만 정확히 한 번 조정한다. 운영 DB의 실제 트리거, picks_with_trades 뷰, 수수료와 결산 규칙을 먼저 추출해 검토해야 한다. 해당 SQL 정의는 현재 저장소에 없다.

모바일은 보유 카드의 배지와 상세 내역으로 설명하고, 데스크톱 표는 수량 옆에 미입고 수량을 표시한다. 관리자 입력은 기존 몇 주당 신주 몇 주인지 적게 하여 “1:1 = 총 2배”를 바로 안내한다.

아이디어 기준가와 목표가도 원본과 기준일을 보존한다. 권리락 전 가격을 현재 주가와 비교할 때만 후속 사건 비율로 환산하고 `무상증자 조정 기준가`를 표시한다. 이미 수정주가인 데이터는 중복 조정하지 않도록 가격 기준과 조정 여부를 저장한다. 과거 시점 수익률에는 그 시점까지의 사건만 적용한다.

## RF머트리얼즈 도입 순서

1. 운영 DB 뷰·트리거·RLS·거래·결산 원본을 확인하고 백업한다.
2. 신규 원장과 계산 RPC를 마련하고 아래 시나리오를 검증한다.
3. RF머트리얼즈 권리락 전 보유분, 이후 거래, 실제 신주 입고 내역과 기존 수동 보정 여부를 대조한다. 화면에 보였던 평균 매수가만으로 대상 수량을 추정하지 않는다.
4. 회원별 영향 미리보기로 수량·평균가·원가·결산 보정 차액을 확인한 뒤 사건을 적용한다.
5. DB와 화면이 같은 계산 버전을 사용하는 상태에서 기능을 공개하고, 홈·보유·매도·결산 수치를 대조한다.

## 필수 검증

- 10주 × 75,500원 → 20주 × 37,750원, 총원가·현금 불변.
- 권리락 후 신규 매수자는 해당 사건 신주 0주.
- 권리락 전 부분매도는 대상 수량 감소, 권리락 후 부분매도는 신주 권리 보존.
- 입고 전 기존 주식을 전량 팔아도 미입고 권리와 배분 원가 유지.
- 입고 전 신주 매도 차단, 실제 입고 후 매도 허용.
- 사건 전후 추가 매수, 부분매도, 전량매도, 재매수 및 연속 기업행사.
- 월별 이월 pick 중복 제거, 여러 회원/포지션 및 단수 배분.
- 적용·입고 중복 요청, 동시 매도, 과거 날짜 거래 삽입, 실패 시 전체 롤백.
- 기존 결산이 있으면 차액만 반영; 정정 후에도 감사 이력과 현금 정합성 유지.
