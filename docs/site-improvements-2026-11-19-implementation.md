# 발표 관리 기능 개선 — 2026-11-19

## 구현 범위

검토 보고서의 1~4번만 구현했다. 자료 링크와 매매 내역 확장은 포함하지 않았다.

- **저장 충돌 방지:** DB의 `edit_revision`으로 조건부 UPDATE한다. 다른 창·사용자·배치가 행을 변경하면 덮어쓰지 않고 원고를 유지하며 최신 내용과 비교할 수 있다. 변경한 항목만 저장하고, 내용만 편집할 때 옛 공통 주제를 다시 쓰지 않는다. 공통 주제의 개별 발표 반영에도 수정 버전을 확인한다. 저장 요청 중에는 입력을 잠가 응답 대기 중 추가 입력이 유실되지 않도록 한다.
- **미저장 내용 복구:** 입력·선택 변경 시 같은 기기의 localStorage에 임시저장한다. 로그인 계정·발표자·발표 ID·일정, 일정 미지정 시 초안 사이클로 구분한다. 재진입 시 복구/폐기를 선택한다. 충돌·네트워크 실패 시 입력을 유지하며 저장 성공 또는 명시적인 폐기 시 임시저장을 지운다. 저장소 사용이 불가능하면 화면에 알린다.
- **일정 복사:** 화면과 동일한 제목 및 공통 주제, 등록된 장소를 복사한다. 장소가 없으면 해당 줄을 생략한다.
- **발표 기록:** PC 검색창, PC·모바일 종목/기타 방식 필터와 고정 사이클 필터를 추가했다. 산업/기업 분류와 발표 방식은 독립적이다. 과거 사이클 미연결 기록도 찾을 수 있다. 기타만 선택하면 수익률 표 대신 기존 내용 요약 카드를 보여준다. 필터는 기기 레이아웃 간 동기화되며 전체 초기화가 가능하다.

## DB 적용 및 배포 순서

1. 사용자가 Supabase SQL Editor에서 `sql/20261119-presentation-edit-revision.sql` 전체를 실행한다.
2. 마지막 조회 결과 `revision_column_ready`, `revision_trigger_ready`가 모두 `true`인지 확인한다.
3. 확인 후 코드 배포를 진행한다. 서비스 워커/페이지 캐시 버전은 `20261119.1`이다.

마이그레이션은 기존 발표 데이터를 보존하며 반복 실행 가능하다. 버전 열과 INSERT/UPDATE 트리거를 추가하고 기존 RLS·권한은 유지한다. 긴 원고 자체를 URL 조건에 넣지 않으므로 원고 길이와 무관하게 짧은 버전 조건으로 충돌을 검사한다. 배포 전 SQL 적용이 필요하며, 열이 없는 상태에서 기존 발표 변경을 시도하면 입력을 보존하고 DB 적용 안내를 표시한다.

## 사용상 범위

임시저장은 해당 브라우저·기기에 보관되며 다른 기기와 동기화되지 않는다. 공통 주제를 여러 발표에 반영하는 중 일부 행이 변경되면 최신 개별 발표를 보호하고 반영 대기 안내를 표시한다. 이 경우 새로고침 후 공통 주제를 다시 저장한다.

기존 로컬 변경인 `js/schedule-shared.js`, `tests/presentation-rotation.test.cjs`와 과거 미추적 문서는 이번 변경에 포함하지 않는다.
